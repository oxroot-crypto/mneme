## 1. Agent 与它的记忆问题

**AI Agent(智能体)** 是一个能循环执行"观察 → 思考 → 行动"的 AI 程序:它接收用户消息,
调用大语言模型(LLM)推理,再调用工具(搜索、写文件、发请求……)完成目标。

类比:LLM 是一个**记性极差但聪明绝顶的顾问**——每次对话结束,它就把你说过的话全忘了
(更准确地说,它一次只能"看见"上下文窗口里的内容,窗口之外一概不知)。
要让这个顾问长期为你工作,必须给它配一个**外部记忆系统**:

- 你上周告诉过它"我喜欢深色模式"——第 40 次对话时它应该还记得;
- 它三年间帮你管理项目,应该记得每个关键决定,而不是每次从零开始;
- 它也该像人一样**忘记**琐碎的中间产物(临时搜索结果),只保留重要的结论。

这个外部记忆系统就是 Mneme 要做的东西。它有两个核心动作:

1. **记住**(写入):把一段信息(对话、事实、决定)存起来;
2. **想起**(读取):当新情况出现时,找出"相关的旧记忆"——注意,是**语义相关**,
   而不是关键词完全匹配。用户问"他偏好什么界面风格?",系统需要想起
   "用户喜欢深色模式"这条记忆,尽管两句话没有一个相同的词。

"语义相关"怎么机械化?这就是嵌入向量的工作,见 §3。

**为什么不用普通数据库?** 传统数据库的查询是精确匹配(身份证号 = 110105...)
或前缀/范围匹配,而记忆检索需要"意思相近"这种模糊匹配——这是一类全新的查询,
需要新的索引结构和存储引擎,这正是向量数据库(vector database)存在的原因。

## 2. RAG:让 LLM "开卷考试"

**RAG(Retrieval-Augmented Generation,检索增强生成)** 是 Agent 使用记忆的标准模式:

```
用户提问 ──► ① 检索:从记忆库找出最相关的 k 条旧记忆
                ② 拼接:把旧记忆塞进提示词
                ③ 生成:LLM 基于提示词回答
```

类比:RAG 就是把 LLM 的"闭卷考试"变成"开卷考试"——不许背(参数里存知识),
但允许翻书(检索记忆库)。考试质量取决于两件事:**翻书翻得准不准**(检索质量),
和**翻得多快**(检索延迟,Mneme 的目标是个位数毫秒)。Mneme 承担的正是"那本书"的角色:
它是一个**嵌入型(embedded,即进程内库,非独立服务)向量存储**。

> 术语:**嵌入型(embedded)** 指像 SQLite 那样作为库链接进你的程序、直接读写本地文件的数据库,
> 与之相对的是 Qdrant/Milvus 那样独立部署、通过网络访问的服务端数据库。
> Agent 框架通常跑在单个进程里,嵌入型意味着零运维、零网络开销。

## 3. 嵌入向量:把"意思"变成"坐标"

### 3.1 直觉

**嵌入(embedding)** 就是:用一个(通常很长的)数字数组来表示一段文本,
并且保证**意思相近的文本,对应的数组在几何上也相近**。

想象一个语义空间:把"猫"和"狗"放在相邻的位置,把"猫"和"微积分"放得很远。
嵌入模型(如 OpenAI text-embedding-3、开源的 BGE 系列)就是一台
"把任意文本放进这个空间"的机器:输入一句话,输出一个固定长度的数组,例如 1536 个小数。
这个数组就叫**向量(vector)**,数组的长度叫**维度(dimension)**,
单个数字叫**分量(component)**。

```
"用户喜欢深色模式"  ──嵌入模型──►  [0.021, -0.113, 0.087, ..., 0.044]   (1536 个数)
"他偏好暗色主题"    ──嵌入模型──►  [0.019, -0.121, 0.083, ..., 0.051]   (与上句非常接近)
"今天股价涨了"      ──嵌入模型──►  [-0.201, 0.044, -0.176, ..., -0.098] (与前两句离得很远)
```

"相近"如何量化?把向量看作高维空间中的**点**(或从原点出发的**箭头**),
用"两点间距离"或"两箭头夹角"来度量。这就是相似度度量,§4 展开。

### 3.2 记号约定

本书用小写粗体字母表示向量:$\mathbf{a} = (a_1, a_2, \dots, a_d)$。
纯文本记法:`a = [a1, a2, ..., ad]`,`d` 表示维度。Mneme 中向量以 `f32`(32 位浮点数,
约 7 位有效数字)存储,默认维度上限 65536,常见嵌入模型维度为 768–3072。

**单位向量(unit vector)**:长度(模)为 1 的向量。向量 $\mathbf{a}$ 的
**范数(norm,即长度)** 记作 $\|\mathbf{a}\|$,
纯文本 `‖a‖`:

$$\|\mathbf{a}\| = \sqrt{a_1^2 + a_2^2 + \cdots + a_d^2}$$

(纯文本:`‖a‖ = sqrt(a1² + a2² + ... + ad²)`)

## 4. 相似度度量:三种尺子

设两向量 $\mathbf{a}, \mathbf{b}$,维度均为 $d$。三种常用度量如下,
Mneme 三者都支持(`Metric::Cosine / Dot / Euclidean`),默认余弦。

### 4.1 点积(Dot Product)

$$\mathbf{a} \cdot \mathbf{b} = \sum_{i=1}^{d} a_i b_i$$

(纯文本:`a·b = a1*b1 + a2*b2 + ... + ad*bd`)

直觉:逐分量相乘再求和。两向量方向越一致、长度越大,点积越大。
它同时编码了"方向相似"和"长度大小"两种信息,因此**没归一化的向量之间不能只比点积**。

### 4.2 余弦相似度(Cosine Similarity)

**只看夹角,不看长度**:

$$\cos\theta = \frac{\mathbf{a} \cdot \mathbf{b}}{\|\mathbf{a}\| \, \|\mathbf{b}\|}$$

(纯文本:`cosθ = (a·b) / (‖a‖ * ‖b‖)`)

- $\theta$ 是两向量的夹角;结果范围 $[-1, 1]$;
- $1$ = 方向完全相同(语义最像);$0$ = 垂直(无关);$-1$ = 完全相反。
- 分子是点积,分母把两向量的长度"除掉",只留方向信息。

**为什么 Agent 记忆默认用它?** 两段文本一个长一个短,只要语义相同,
余弦相似度就接近 1;而点积会被长文本(分量普遍更大)干扰。嵌入模型大多为余弦设计。

### 4.3 欧氏距离(Euclidean Distance)

就是"两点间直线距离":

$$\text{dist}(\mathbf{a}, \mathbf{b}) = \sqrt{\sum_{i=1}^{d}(a_i - b_i)^2}$$

(纯文本:`dist = sqrt( (a1-b1)² + (a2-b2)² + ... + (ad-bd)² )`)

距离越小越相似。展开后有一个工程上重要的恒等式:

$$\|\mathbf{a}-\mathbf{b}\|^2 = \|\mathbf{a}\|^2 + \|\mathbf{b}\|^2 - 2\,\mathbf{a}\cdot\mathbf{b}$$

(纯文本:`dist² = ‖a‖² + ‖b‖² − 2*a·b`)

**【工程含义】** 计算欧氏距离可以复用点积的核心循环(乘加),
且 $\|\mathbf{a}\|^2$ 可以在写入时预计算存起来——于是查询时只需一次点积。
这是 [02 原语层](02-l0-core.md) 中 SIMD 核只需实现"点积"一种内核的原因。

### 4.4 三者关系

- 余弦 = 归一化后的点积:若 $\|\mathbf{a}\| = \|\mathbf{b}\| = 1$,则 $\cos\theta = \mathbf{a}\cdot\mathbf{b}$;
- 对归一化向量,欧氏距离与余弦单调等价:$\|\mathbf{a}-\mathbf{b}\|^2 = 2 - 2\cos\theta$。
  所以"余弦最相似 = 欧氏最近",选哪个不影响排序,只影响数值含义。

### 4.5 算例(手算)

取 $d = 4$:$\mathbf{a} = (1, 0, 2, 1)$,$\mathbf{b} = (0, 1, 1, 2)$。

```
点积:  a·b = 1*0 + 0*1 + 2*1 + 1*2 = 4
范数:  ‖a‖ = sqrt(1+0+4+1) = sqrt(6) ≈ 2.449
        ‖b‖ = sqrt(0+1+1+4) = sqrt(6) ≈ 2.449
余弦:  cosθ = 4 / (2.449 * 2.449) = 4 / 6 ≈ 0.667
欧氏:  dist² = 1+0+4+1 + 0+1+1+4 − 2*4 = 12 − 8 = 4  →  dist = 2
验证:  (a−b) = (1,−1,1,−1),dist² = 1+1+1+1 = 4 ✓
```

### 4.6 复杂度

| 运算 | 时间 | 空间 | 说明 |
|---|---|---|---|
| 点积 / 余弦 / 欧氏(单对) | $O(d)$ | $O(1)$ | 逐分量一遍;SIMD 可降至约 $O(d/8)$ 次向量指令,见 [02](02-l0-core.md) |
| 范数(单向量) | $O(d)$ | $O(1)$ | 写入时算一次,存起来 |

## 5. 为什么需要专门的向量库:暴力检索撑不住

### 5.1 暴力扫描(brute-force scan)

最朴素的"想起"实现:**拿查询向量与库中每一个向量算一次相似度,取最高的 k 条**。
设库中有 $N$ 条记忆,每次查询:

$$T_{\text{brute}} = O(N \cdot d)$$

(纯文本:每次查询 = N 次相似度计算,每次 O(d))

**算例**:一个活跃使用两年的 Agent,$N = 100$ 万条 1536 维记忆:

```
每次查询 ≈ 1,000,000 × 1536 ≈ 15.4 亿次乘加
现代 CPU 单核 SIMD ≈ 每周期 16 次乘加,3 GHz ≈ 480 亿次乘加/秒
→ 单查询 ≈ 32 ms,且占满一个核;100 个 Agent 并发时彻底不可用
```

结论:$N$ 到几万以上,暴力扫描的延迟/功耗就不可接受(但注意:Mneme 在 $N$ 较小时
**仍然用暴力扫描**——简单、精确、零索引维护成本;索引是 $N$ 大之后的优化,见渐进式分层)。

### 5.2 近似最近邻(ANN):用少量"不准"换百倍速度

**近似最近邻检索(ANN, Approximate Nearest Neighbor)** 的思想:
**不求找到数学上绝对最近的邻居,只求以很高概率找到它们,同时把查询降到亚线性复杂度**。

衡量两个指标:

- **召回率(Recall@k)**:ANN 返回的 top-k 中,有多少条与暴力扫描的"标准答案"重合。
  `Recall@10 = 0.95` 表示平均每次能找回 10 个真邻居里的 9.5 个。
- **延迟(Latency)**:单次查询耗时,Mneme 目标 1M 条数据 P99 < 10ms(量化后,见 [08 章](08-l6-quant.md))。

两者是一对跷跷板:放得更"近似"一点,速度就更快,召回略降。所有 ANN 索引
(HNSW、IVF、DiskANN……)本质都是**在"索引大小/构建时间/查询延迟/召回率"四者间做取舍**。
Mneme 选用 **HNSW**(分层可导航小世界图),其完整数学在
[05 章](05-l3-hnsw.md)——那里会从"六度分隔"讲起,零基础可读。

## 6. 数据库经典机制科普:八个名词

Mneme 的持久层([04 章](04-l2-persist.md))组合了以下经典机制。
这里只建立直觉,细节与复杂度推导在各章展开。

### 6.1 页缓存与 fsync:数据"写出去"了 ≠ 落盘了

程序调用 `write()` 后,数据通常只进了操作系统的**页缓存(page cache,内存里的写缓冲区)**,
并没有写到磁盘。机器此时断电,数据就丢了。`fsync()` 系统调用强制操作系统把缓存刷到
物理盘,**返回即代表数据真正持久**。但每次 fsync 都要等待磁盘确认(约 0.1–10ms,
盘型而定,见 [04 §3.4](04-l2-persist.md)),太频繁会拖垮吞吐。
于是有了经典权衡——**fsync 策略**:

| 策略 | 语义 | 代价 |
|---|---|---|
| Always | 每条写都 fsync | 断电最多丢 0 条(已确认的);吞吐最差 |
| Batched(如 20ms) | 每 20ms 攒一批 fsync | 断电最多丢 20ms 内的写入;吞吐好 |
| OnFlush | 只在显式 `flush()`/`close()` 时 fsync | 断电丢自上次 flush 后的写入;吞吐介于 Batched 与 Never |
| Never | 从不主动 fsync(交给 OS) | 断电可能丢较多;吞吐最好 |

Mneme 把它做成配置项 `FsyncPolicy`,默认 `Batched(20ms)`——对 Agent 记忆,
丢 20ms 的写入(通常一两条)远比拖慢对话重要。

### 6.2 WAL(预写日志):先记账,后入册

**WAL(Write-Ahead Log,预写日志)** 是一个只追加(append-only)的日志文件:
任何修改先以"操作流水"形式追加到 WAL 并(按策略)fsync,**然后**才应用到正式数据结构。

类比:会计先在流水账上记一笔"收到 100 元",再腾手去更新总账;哪怕总账更新到一半崩溃,
流水账还在,照着重放就能恢复。

WAL 带来两个性质:

- **顺序写**:磁盘(尤其 SSD)最擅长顺序追加写入,随机写则慢得多;
- **崩溃恢复**:重启时重放 WAL 中未应用的记录即可还原状态。

"已 fsync 的写入永不丢、未 fsync 的写入当作没发生"——这是崩溃一致性的底线,
也是 [09 测试](09-testing.md) 中崩溃注入测试要验证的核心不变量。

### 6.3 CRC 校验:检测"写了一半"的字节

断电可能发生在写入的**任意一个字节中间**(术语:**撕裂写,torn write**),
磁盘也可能老化出坏块。**CRC(Cyclic Redundancy Check,循环冗余校验)** 是给数据块
附加的一小段"指纹"(Mneme 用 CRC-32,4 字节):数据任何 1 个 bit 变化,
指纹都会对不上。WAL 的每一帧都带 CRC,恢复时指纹不符的尾部帧直接丢弃——
**绝不能把写了一半的数据当完整数据用**。

直觉理解 CRC:把数据字节流看作一个巨大的二进制数,用一个约定的"生成多项式"去除它,
**余数**就是 CRC。除法对每一位都敏感,所以任何 bit 翻转都会改变余数。
CRC 不是加密,防不了恶意篡改,但能检出所有长度 ≤ 32 bit 的连续突发错误。

### 6.4 墓碑删除:先标记,后清扫

在追加式(LSM 风格,LSM = Log-Structured Merge,只追加写、后台合并的存储组织方式)存储里,
删除一条记录**不是**原地抹掉(旧数据在不可变文件里),
而是写入一条"**第 1234 号记录已删除**"的标记——这个标记叫**墓碑(tombstone)**。
查询时跳过带墓碑的记录;后台**合并(compaction)** 时才把旧数据与墓碑一起物理清除。

类比:图书馆不撤下旧书,而是在目录卡片上盖"已下架"章;每月大扫除时才真正搬走,
顺带把目录重新整理一遍。

### 6.5 Compaction(合并压缩):超长期不失控的关键

追加写让旧文件越积越多,墓碑让有效数据占比越来越低。**compaction** 是后台线程:
挑选几个小段文件,把它们的有效记录**合并重写**成一个新段,顺带完成
物理删除、TTL 清理([07 章](07-l5-life.md))和索引重建。
精心设计的合并策略能保证:**活跃文件数有上界、写放大(见 §6.7)可预测**——
这就是 Mneme 敢承诺"超长期记忆不失控"的底气。

### 6.6 MVCC 与 seqno:让读者看到一致的快照

**MVCC(Multi-Version Concurrency Control,多版本并发控制)**:读操作不等写操作,
而是看到某个时刻的一致性快照。Mneme 的实现很轻(因为单写者):全局维护一个单调递增的
**序号(seqno)**,每条记录提交时盖一个序号;读操作拿住一个**水位(watermark)** W,
只看得见 `seqno ≤ W` 的记录——写入的同时,读到的永远是完整一致的过去。

### 6.7 写放大(Write Amplification)

compaction 不是免费的:同一条数据可能被"重写"多次。**写放大系数** =
实际写入磁盘的字节数 ÷ 用户逻辑写入的字节数。size-tiered 合并的写放大约为
$O(\log_r N)$($r$ 为分级比例,推导见 [07 章 §4](07-l5-life.md)),
量级只有几倍,这是可接受且可预测的。

### 6.8 mmap:把文件当内存用

**mmap(内存映射文件)** 让操作系统把文件内容"映射"进进程地址空间:
程序像读普通数组一样读文件,实际发生缺页时由 OS 按需把文件的那一页调入内存。
好处:**零拷贝、按需加载、内存占用由 OS 页缓存自动管理**——
冷数据(很久没访问的旧段)自动换出,热数据常驻。Mneme 的向量与图索引文件
默认用 mmap 读(可关闭),这是"1M 条记忆冷启动 < 1 秒"的关键。

## 7. 附录:大 O 记号速成

$O(f(n))$ 读作"当规模 n 增大时,耗时(或空间)的增长速度不超过 f(n) 的常数倍"。
它描述**增长趋势**,不关心具体常数。

| 记号 | 名字 | 直觉例子 |
|---|---|---|
| $O(1)$ | 常数 | 数组按下标取值;查一次哈希表 |
| $O(\log n)$ | 对数 | 有序数组二分查找:100 万数据约 20 步 |
| $O(n)$ | 线性 | 暴力扫描一遍所有向量 |
| $O(n \log n)$ | 线性对数 | 排序;建一次 HNSW 索引 |
| $O(n \cdot k)$,k 为常数 | 线性(常数大) | 暴力检索 top-k |
| $O(n^2)$ | 平方 | 两两比较所有向量对 |

本书所有复杂度默认指**时间**;**空间复杂度**单独标注,常以"每条记录多少字节"给出。

## 8. 串起来:一次"想起"的全流程预览

用户问 Agent:"他偏好什么界面风格?" 以下是 Mneme 内部发生的事(标注各章):

```
① Agent 把问题交给嵌入模型 → 查询向量 q (1536 维)            [00 §3,本章]
② q 进入命名空间 ns("agent-42")                               [07 生命周期]
③ 过滤 DSL 编译:importance > 0.5 → 每段生成候选位图,        [06 检索层]
   zone map/bloom 剪掉不合格的数据块                          [04 持久层]
④ 选择性评估 → 三档过滤策略 → 各段并行 HNSW 搜索              [05 HNSW]
```
