## 1. 问题设定

给定库中 $N$ 个向量 $\{v_i\}$ 与查询向量 $q$,要找相似度最高的 $k$ 个("最近邻")。
暴力扫描 $O(N \cdot d)$([00 §5.1](00-fundamentals.md)),太大。
HNSW 属于**基于图**的 ANN:预先把向量组织成一张图,**沿着"越来越近"的边走**,
几步之内到达邻居,而不必看所有点。

核心不变量:**图中每个点都有一条边连向它的近邻** → 从任意点贪心走,
每步都更接近目标 → 步数与 $N$ 只呈对数关系(下面证明直觉)。

## 2. NSW:小世界与贪心路由

### 2.1 【直觉】六度分隔

社交网络有个著名现象:任意两个人之间,平均只要通过约 6 个朋友就能建立联系。
这样的网络叫**小世界(small world)网络**:每个节点只认识少数人(度数小),
但任意两点间的路径却出奇地短。HNSW 的底层 NSW(Navigable Small World,可导航小世界)
就是把向量库变成一张小世界图:**点 = 向量,边 = "这对向量互为近邻"**,
查询 = "从某个入口出发,不断走向与 $q$ 更近的朋友,直到无法更近"。

### 2.2 【数学】为什么贪心路由是 $O(\log N)$

贪心路由(greedy routing):当前位置 $c$,考察 $c$ 的 $M$ 个邻居,
移到"距 $q$ 最近"的邻居;无更近者则停(局部最小)。

- 若图是 $d'$ 维随机几何图(边连近邻),从任意点到目标点的贪心步数
  与"覆盖距离所需倍缩次数"同阶:每一步把剩余距离缩到常数比例,
  步数 $= O(\log N)$(经验结论;对一般图无闭式严格界,原论文给出
  多项式对数的实验与启发式论证)。直观版:若每个点只连最近的邻居,
  一维数轴上从 0 走到 N 要 $O(N)$ 步;只有当部分边是**长程边**(能一次跨过
  大部分距离)时,每步才能把剩余距离缩到常数比例,从而约 $\log N$ 步走完
  ——这正是小世界网络"短边 + 少量长程边"的关键。
- **局部最小陷阱**:真实高维数据里,贪心会卡在"比所有邻居都远但不是全局最近"的点。
  NSW 的答案是**加长程边**(老论文用 $O(\log N)$ 次随机重启/捷径),
  HNSW 的答案更优雅:**分层**,见下节。

## 3. 分层结构:每层是一个"更稀疏的小世界"

### 3.1 【直觉】高速公路与乡道

在一层图里,长程跳转与短程精修是矛盾的。HNSW 的解法像交通网:**顶层是高速公路**
(节点极稀疏,一条边跨半个国家),**底层是乡道**(所有点都在,边连紧邻)。
查询先上高速奔向大致区域,逐层下高速,最后在乡道上精确导航。
这与跳表(skip list)的分层思想同源,只是把有序链表换成了近邻图。

### 3.2 【数学】层级分配:几何分布

每个点插入时掷一次骰子决定它的最高层级:

$$\text{level} = \left\lfloor -\ln(u) \cdot m_L \right\rfloor, \qquad u \sim \mathrm{Uniform}(0,1),\quad m_L = \frac{1}{\ln M}$$

**推导** $P(\text{level} \ge l)$:

$$
P(\text{level} \ge l) = P(-\ln u \cdot m_L \ge l) = P\big(u \le e^{-l/m_L}\big) = e^{-l/m_L}
\overset{m_L = 1/\ln M}{=} e^{-l \ln M} = M^{-l} = \left(\frac{1}{M}\right)^l
$$

即**每升一层,存在概率除以 M**。由此:

| 量 | 值($M=16$) | 推导 |
|---|---|---|
| $P(\text{level} \ge 1)$(在某上层) | $1/16 = 6.25\%$ | 直接代入 |
| $P(\text{level} \ge 2)$ | $1/256 \approx 0.39\%$ | 同上 |
| 节点期望层数(参与的层数) | $\frac{M}{M-1} \approx 1.07$ | $\sum_{l\ge0} P(\ge l) = 1/(1-1/M)$ |
| 期望最高层 | $\log_M N$ | 第 $l$ 层节点数 $= N/M^l$;最高层 ≈ 1 个节点当 $N/M^l \sim 1$ |

$N = 10^6$ 时 $\log_{16} 10^6 \approx 5$ 层;每段的入口点几乎总落在顶层(存于该段 hidx 头部,§10)。

**为什么选 $m_L = 1/\ln M$?** 它使"上层节点数按 $1/M$ 递减",从而
① 任意层的度数上界 $M$ 保持图稀疏;② 层高只有 $O(\log_M N)$;
③ 单层图规模每层缩 $M$ 倍——查询自顶向下时,每层的"搜索半径"恰好缩小约 $M$ 倍,
与度数匹配(§6 的复杂度推导依赖这一点)。

## 4. 构建算法:逐点插入

记号:$\text{dist}(x, y)$ = 距离(小 = 近);$M$ = 上层度数上限;
$M_0 = 2M$ = 第 0 层度数上限;$ef_c$ = 构建期候选队列宽度(默认 200)。

### 4.1 核心子程序 `SEARCH-LAYER(q, entry_points, ef, layer)`

```text
W ← TopK(ef, 保留最优 ef 个;根 = 当前最差者,便于淘汰)   # 结果集,"最优/最差"由 Metric::better 判定
C ← 小根堆(按 dist) 装 entry_points                  # 候选集,最近的优先出
V ← 空集(已访问)
while C 非空:
    c ← C.pop_min()                    # 当前最近的候选
    if dist(c,q) > W 的最远值 且 |W| = ef: break      # 剪枝:没有希望更近了
    for e in c 的邻居(layer 层) 且 e ∉ V:
        V ← V ∪ {e}
        if |W| < ef 或 dist(e,q) < W 最远值:
            C.push(e); W.push(e)
            if |W| > ef: W.pop_farthest()
return W
```

两个堆的分工:候选堆 C 负责"往外探"(优先看近的),结果堆 W 负责"守住前 ef 名"。
剪枝条件 `dist(c,q) > W 最远值` 是复杂度的关键——它保证探查的节点数 ≈ ef 而非 N。

> **记号警告**:伪代码里的 `dist` 是**抽象距离**,统一约定"越小越近";对 `Dot`/`Cosine`
> 而言分数是越大越优,实际比较一律走 `Metric::better`([02 §3](02-l0-core.md)),
> **绝不直接比较 `score` 数值**。实现时把 `dist(c,q)` 理解为"c 相对 q 的优劣序位"即可。

### 4.2 插入一个新点 $q$

```text
1. level ← 掷骰子(§3.2)
2. ep ← 当前入口点
3. for l ← 最高层 down to level+1:            # 上层:纯贪心下降,ef=1
       ep ← SEARCH-LAYER(q, {ep}, ef=1, l) 的最近者
4. for l ← min(level, 最高层) down to 0:      # 目标层及以下:完整搜索 + 连边
       W ← SEARCH-LAYER(q, {ep}, ef=ef_c, l)
       neighbors ← SELECT-NEIGHBORS(q, W, M(l))          # 见 §4.3
       for e in neighbors: 建双向边 (q↔e)
       for e in neighbors:                                # 邻居超员则修剪
           if e 在 l 层的度数 > M(l): e 的邻集 ← SELECT-NEIGHBORS(e, 其邻集, M(l))
       ep ← W 中最近者
5. if level > 当前最高层: 段内入口点 ← q,登记进该段 hidx(§10)
```

### 4.3 启发式选邻 `SELECT-NEIGHBORS`(多样性剪枝)

朴素选法"取距 $q$ 最近的 M 个"会让图**方向单一**(邻居挤在同一象限),
路由容易死路。启发式规则:

```text
candidates ← W 按 dist(c,q) 升序;  R ← 空集
for c in candidates:
    if R 为空 或 对所有 r ∈ R: dist(c, q) < dist(c, r):   # c 与 q 的距离小于 c 与任一已选 r 的距离(即 c 未被 r 代表)
        R ← R ∪ {c}
    else 丢弃(c 被某个已选 r "代表"了)
    if |R| = M: break
(可选)不足 M 时从被丢者回填
```

**【直觉】** 条件 `dist(c,q) < dist(c,r)` 的含义:"q 是 c 的近邻,比 c 的任何
已选邻居 r 都近"——即 c 能提供 r 们提供不了的信息(不同方向的入口)。
若 c 离某个已选的 r 很近,那走 r 也能到 c 附近,c 就是冗余的。

**【算例】** $q$ 周围三个候选:西边 1.0、西北 1.1、西偏北 1.2(彼此都近):

```
c1=西 1.0   → R 空,选入 R={西}
c2=西北 1.1 → dist(c2,q)=1.1 < dist(c2,西)=0.4? 否 → 丢弃(被西代表)
c3=西偏北 1.2→ dist(c3,q)=1.2 < dist(c3,西)=0.3? 否 → 丢弃
结果 R={西}。若来一个东边 5.0 的 c4: dist(c4,q)=5.0 < dist(c4,西)=5.5? 是 → 选入,提供新方向 ✓
```

### 4.4 【复杂度】构建

单点插入的距离计算次数:

- 上层贪心($\le \log_M N$ 层 × 每层 ≤ $M$ 邻居):$O(M \log_M N)$;
- 目标层 `SEARCH-LAYER`:探查节点 ≈ $ef_c$,每节点展开 ≤ $M_0$ 邻居
  → $O(ef_c \cdot M_0)$;
- 每次距离计算 $O(d)$(SIMD,见 [02 §4](02-l0-core.md))。

$$T_{\text{insert}} = O\big(d \cdot (ef_c M_0 + M\log_M N)\big) \approx O(d \cdot ef_c \cdot M_0)$$

$$T_{\text{build}}(N) = O(N \cdot d \cdot ef_c \cdot M_0), \qquad S_{\text{graph}}\ \text{(see §6.3)}$$

**工程注**:上述是**单线程**界;构建天然可并行(不同点并发插入,连边阶段加细粒度锁),
Mneme 用 scoped threads 按批并行。50k 向量/秒的目标依赖批内并行 + 常见维度(768–1536)
的 SIMD 吞吐,基准验证见 [14 §4](14-testing.md)。

> **L3 落地状态**:当前 `HnswIndex::build` 为**串行**构建(固定种子,同输入同图便于复现);
> 批内并行尚未接线(L5 compaction 也仍为单线程顺序执行,见 [07 §4.4](07-l5-life.md))。
> 1M×1536 的吞吐/延迟基准尚未接入 CI,`benches/hnsw.rs` 当前只是微缩趋势样本。

## 5. 查询算法

```text
SEARCH(q, k, ef):
  ep ← 段内入口点(自 hidx 头部,§10)
  for l ← 最高层 down to 1: ep ← SEARCH-LAYER(q, {ep}, ef=1, l) 最近者
  W ← SEARCH-LAYER(q, {ep}, ef=max(ef, k), 0)
  按 better() 排序取前 k(过滤版见 §9)
```

`ef`(explore factor,探查宽度)是**召回/延迟的旋钮**:$ef = k$ 是下限(召回低);
经验上 $ef \gtrsim 8k$ 起召回显著改善,而本书的验收门槛 Recall@10 ≥ 0.95 统一取
**$ef = 128$**(见 [14 §3](14-testing.md)),默认值 64 为延迟优先,需按需上调。

**【算例】8 个点手算**:数轴上点 0..7(向量即标量,距离 = 差的绝对值),
$M=2, M_0=4$,插入顺序 0..7,设 3 与 7 掷得 level=1,其余 level=0,
$ef_c=4$。

```text
建图后(示意):
  第 1 层: 3 ── 7                    (稀疏高速)
  第 0 层: 0-1-2-3-4-5-6-7 每点连左右各 ≤4 近邻   (全量乡道)

查询 q=6.4, k=1, ef=2, 入口=3:
  第 1 层: {3,7} 中 dist(7,6.4)=0.6 < dist(3,6.4)=3.4 → ep=7   (一次跨域)
  第 0 层: 从 7 探: 邻居 {6,5,4…}; W 收 {7:0.6, 6:0.4}; 候选探 6 → 邻居 5: dist 1.4 > 0.6 剪枝
  返回 top1 = 6 ✓
总距离计算: 4 次(而非 8 次;被剪枝的 5 也要算一次距离)——N 大时节省随 N 呈数量级放大。
```

## 6. 复杂度总表

### 6.1 时间

| 操作 | 界 | 默认参数代入 |
|---|---|---|
| 单点插入 | $O(d \cdot ef_c \cdot M_0)$ | 1536 维 ≈ 200×32 ≈ 6400 次距离计算(每次一个点积) |
| 构建全库 | $O(N \cdot d \cdot ef_c \cdot M_0)$ | — |
| 单次查询 | $O(d \cdot ef \cdot M_0)$ 上界;**实测**距离计算 ≈ (2–5)×ef(经验值) | ef=128 → 数百~千次点积 |
| 上层下降 | $O(d \cdot M \cdot \log_M N)$ | ≤ 5 层 × 16 邻居 |

对比暴力 $O(N \cdot d)$:$N = 10^6$,查询读取向量数从 $10^6$ 降到 ~$10^3$,
**三个数量级**——这就是 P99 < 10ms 目标的来源([14 §4](14-testing.md) 验证)。

### 6.2 召回率

无严格闭式(图搜索是概率过程);保证方式是**门槛验收 + 边界/属性测试**:
Recall@10 ≥ 0.95(ef=128,随机均匀 + 8 簇合成数据两套固定种子数据,见 [14 §3](14-testing.md))。
调参方向:$ef \uparrow$ → 召回↑延迟↑;$M \uparrow$ → 召回↑,空间/构建时间↑。

> **L3 落地口径**:当前 CI 档验收为微缩规模(2500 条 × 32 维、默认 `HnswParams`,
> 两套分布分别达标,见 `tests/hnsw_contracts.rs`);设计规模(64 维 10 万条 × 2 套)
> 属 heavy/夜间档,尚未接线(设计规模不改变门槛语义,只提高统计置信度)。

> **确定性边界**:HNSW 的构建(并行插入)与 compaction 重建都会改变图的邻接结构,
> 因此**同一逻辑数据集在 compaction 前后、或两次重建之间,近似结果可能不同**。
> 引擎只承诺:①同一快照内结果全等([03 §2.2](03-l1-memory.md));②`ef → ∞` 时收敛于
> 精确结果(§12);③Recall@10 的统计门槛。需要跨重建可复现时,请用 `ef` 足够大或
> 走暴力扫描(段行数不超过 `brute_force_max_rows` 时恒暴力,[16 §2](16-api-reference.md))。

### 6.3 空间

**邻接表**:第 0 层每点 $M_0$ 个 u32 槽;上层"成员期望数"为
$\sum_{l\ge1} P(\ge l) = \frac{1/(M)}{1-1/M} = \frac{1}{M-1}$,
每成员 $M$ 个 u32 槽(按容量预留)→ 期望 $4\frac{M}{M-1}$ 字节:

$$S_{\text{node}} = \underbrace{4 M_0}_{=8M\ \text{bytes}} + \underbrace{\frac{4M}{M-1}}_{\text{upper levels}} + \underbrace{\approx 16}_{\text{NodeMeta\{level,offset\}}} \approx 8M + 20\ \text{bytes}$$

**【算例】** $M=16$:

| 项 | 每节点 | 1M 节点合计 |
|---|---|---|
| 图邻接(hidx) | ≈148 B | ≈148 MB |
| 向量 f32(1536 维) | 6144 B + 4 B norm | ≈6.1 GB |
| 合计 | — | ≈6.3 GB(mmap 主要驻磁盘,内存按页缓存浮动) |

> **节点数 = 保留的物理版本数(含历史版本)**:每个未回收的版本都是一个节点(§7)。
> 历史版本越多,hidx 与向量区越大;`history_horizon` 有限时可把节点数约束在窗口内。
> 下表按"1M 个版本"计,不是"1M 条逻辑记录"。

结论:**图索引的开销只有向量的 ~2.4%**;真正的大头是向量本身——这就是
[08 量化](08-l6-quant.md)(字节 ÷4)的意义所在。

### 6.4 与排序层的协同(时间感知 ANN)

HNSW 的剪枝只依赖**向量距离**;而 [10](10-scoring.md) 的综合排序还含新鲜度/重要度/
访问/可信度,这些量与距离不相关,不能直接进剪枝(会破坏召回)。因此:

- **默认(落地口径)**:HNSW 用原始相似度粗排(取用户 `ef`),再由 [10 §2.3](10-scoring.md)
  综合重排;设计中的候选放大 `ef' = max(ef, 4k)` **尚未接线**(见 [10 §2.3](10-scoring.md)
  的落地状态);
- **可选重要性偏置路由**(`Scoring::bias_routing`):遍历优先级用
  `dist / √(1 + β·imp + β·acc)` 作为启发式(β 为实现内部固定系数,默认 1.0,不对外暴露),
  **只改访问顺序、不改最终分**,在不显著损召回的前提下减少探查量;这是"时间感知 ANN"的
  工程形态;**当前设置即返回 `Unsupported`**(未落地,绝不静默无效,FC-MEM-ERR-002)。

## 7. 删除:墓碑与图的一致性

图索引的删除是出名地难(边失效、入口点悬空)。Mneme 的策略**保守而正确**:

| 机制 | 规则 |
|---|---|
| 墓碑位图 | 段级 `dead` 位图(vsec 内,[04 §2.1](04-l2-persist.md));O(1) 判定 |
| 搜索期 | **遍历可以穿过死节点**(保持图连通性),**结果**只收活节点(`W.push` 前查位图) |
| 版本可见性 | 每个保留的物理版本(含历史版本)都是一个 HNSW 节点;搜索传入的 **alive 位图**决定可见版本:当前搜索 = 每个 RowId 的最新可见版本,`as_of(T)` = 每个 RowId 中 `tx_ms ≤ T` 的最新可见版本([04 §2.2](04-l2-persist.md))。历史版本可穿越、仅当被 alive 位图选中才可入选 |
| 入口点死亡 | 每段在 MANIFEST 的 `SegmentEntry.entry_*` 与 hidx 头部各存一个段内入口([04 §2.4](04-l2-persist.md)、[§10](05-l3-hnsw.md))。**L3 落地**:入口节点不保证存活,搜索靠"可穿死节点"仍正确;死亡入口由 L5 compaction 整体重建(`src/index/rebuild.rs`)随幸存槽位重选,MANIFEST 的 `entry_*` 仍只是信息登记,载入以 hidx 头部为准 |
| 图修复 | **不做单点重连**(易碎且贵);物理清理交给 compaction 时的整体重建([07 §4](07-l5-life.md)),重建即重新执行 §4 构建,并行化 |

失效模式分析:死节点比例 $t$ 时,搜索多走的"废路"以 $O(t \cdot ef)$ 计,
$t < 25\%$(compaction 触发线,[07 §4](07-l5-life.md))内召回影响 < 1%(经验值)——
超过就重建,把最坏情况关在笼子里。

> **历史版本对当前搜索的影响**:历史版本(仅 `as_of` 可选中、当前搜索不可选)同样计入
> "非当前节点"比例。`history_horizon` 越长、更新越频繁,该比例越高,当前搜索的召回/延迟
> 退化越明显。更新密集型负载建议设置有限 `history_horizon`(如 90 天),并在召回下降时
> 触发 compaction 重建(§4)。`as_of` 查询本身可用同一张图(换 alive 位图)或对版本链
> 暴力扫描,由计划器按候选规模择一([04 §2.2](04-l2-persist.md))。

## 8. 过滤三档策略:`filtered.rs`

**问题**:带过滤的检索(如 `kind == "fact"`)如果搜完再筛(后过滤),
可能返回不足 k 条;如果只沿"过滤内"节点走(预过滤),图可能断连。Mneme 按选择性
$s = |\text{cand}| / N_{\text{alive}}$ 自适应三档:

| 档 | 条件 | 策略 | ef 调整 |
|---|---|---|---|
| ① 后过滤 | $s > 0.10$ | 全图遍历(与档②共用)+ 结果集过滤 | $ef' = \max(ef,k) \cdot \min(8,\ 1/s)$ |
| ② 放大后过滤 | $0.001 < s \le 0.10$(且候选数 ≥ `max(ef,1024)`) | **全图遍历**(保连通)+ 结果限候选 | $ef' = \max(ef,k) \cdot 4$ |
| ③ 候选暴力 | $s \le 0.001$ 或候选数 < `max(ef, 1024)`(仅当存在过滤位图;无过滤时候选即 alive、$s=1$,按 `post_threshold` 走档①/②) | 直接对候选位图暴力扫描 | — |

> **实现注**:原设计档②为"约束遍历(只展开过滤内节点)",但过滤稀疏时图会被候选位图
> 切断,`ef` 再放大也探不到足够候选,召回近乎归零(已由候选数阈值兜底)。落地改为
> **全图遍历、结果限候选**——遍历不受限(保持图连通),最终 `TopK` 只收候选位图内节点,
> 仍严格满足"结果 ⊆ alive ∩ 过滤位图"且统计等价于候选暴力。档①②的区别仅剩 `ef'` 放大倍数。

> **召回与探查密度的关系(档①②的后过滤口径)**:遍历 `ef'` 个节点中期望命中候选
> ≈ `ef' · s`(探查优先靠近查询,实际略优于随机期望)。要让 top-k 的统计等价成立,
> 应满足 `ef' · s ≳ 4k`(经验系数,验收测试 `tests/hnsw_contracts.rs::filter_amplified_tier_matches_candidate_bruteforce`
> 在 `s=0.05, ef'=2048` 下验证 Recall@10 ≥ 0.95)。`ef' · s` 过小时(大 N × 极低 s)
> 后过滤召回必然下降——此时应提高 `ef`,或依赖档③候选暴力(其代价 `O(s·N)` 仍远低于
> 全量扫描)。本节的"统计等价"均以该条件为口径;这也是 §11.1 "召回不够先加 ef" 的量化依据。

- 候选位图来自 L4 的 zone map/bloom 下推([06 §2](06-l4-query.md)),位图本身
  $O(N/8)$ 字节、popcount 求 $s$ 为 $O(N/64)$ 字操作——亚微秒;
- **"后过滤"不违反 I6**:候选位图仍在遍历前算好(过滤先行、融合只作用于过滤后候选);
  档①只是遍历期不做位图剪枝、靠放大 $ef'$ 后过滤以保召回,与 I6 的"过滤先于融合"不矛盾;
- **与 [10 §2.3](10-scoring.md) 的排序放大叠加**:同时开启过滤与综合排序时,先按本表放大
  $ef'$ 以保过滤召回,再按排序需求取候选;两者都只改探查宽度,不改语义;
- 三档的**正确性标准**:结果集 ≡ "候选位图内暴力扫描"的结果(统计等价,
  验收见 [14 §3](14-testing.md));策略只影响速度,不影响(近似)召回语义;
- 阈值 0.10 / 0.001 为默认,可配;依据:①档时后过滤的"浪费率" ≤ 90% 仍划算;
  ②档图连通性在候选 > 0.1% 时实验上足够(经验值,基准覆盖)。

> **常见误区**:三档是**性能策略**而非语义开关——三档结果都必须等价于"候选位图内暴力"。
> 若某档结果不同,是 bug 而非预期;阈值调的是速度,不改变(近似)召回语义。

## 9. 跨段归并:`merge.rs`

> **落地状态**:L5 之前每次 flush 只保留一个活跃段,故 L3 的"多段图"退化为
> **单个索引前缀 + 未建树尾扫描**:查询 = 前缀 ANN(`filtered.rs`)+ 尾部暴力,
> 二者以 L0 `TopK::merge` 归并(见 `src/memory/search.rs`)。L5 起多段并存已落地,
> 查询按 MANIFEST 段序**串行**逐段归并(`merge` 仍由 `TopK::merge` 承担);
> 下述 scoped threads 并行模型与独立归并模块是**目标形态**、尚未接线。

库由多个段组成(追加式存储),每段有自己的图。查询 = 各段搜索 + 全局归并:

```text
逐段(当前实现:串行;目标形态:scoped threads 并行):
    每段 → 选择 HNSW / 暴力(段行数 ≤ 2048 恒暴力) → 段内 TopK(k)
归并: k 路分数归并([02 §5 TopK.merge]) → 全局 top-k
```

段内 TopK 的容量取 $k$(不是 ef):召回由段内 ef 保证,跨段只需前 k,
归并代价与段数成线性、极小。(L4 混合检索时每个通道各取 $2k$ 再融合,
见 [06 §5](06-l4-query.md);这里 $k$ 指纯向量检索路径。)

> **可变表(内存段)**:尚未 `flush` 的记录不在任何 HNSW 中,查询时作为一个"内存段"
> 直接暴力扫描(其规模通常远小于 `brute_force_max_rows`),与各段 TopK 一起归并——
> 因此新写入无需 `flush` 即可被检索([04 §8](04-l2-persist.md))。

## 10. hidx 文件布局(简)

```text
0   magic "HID1" | u16 ver | M u16 | M0 u16 | efc u16 | ml f32 | u32 count
    entry: (u32 slot, u8 level)           # 段内入口(节点 = SlotId)
    node_table_offset / len, adj_offset / len, header_crc32
node_table: [(u8 level, u32 adj_off)] × count     # 定长,O(1) 定位
adj_blob:   逐点逐层 [u16 degree] + u32 邻居槽位数组(层0 ≤ M0 个,上层按 level ≤ M 个)
尾部 payload_crc32
```

> 上图为**简图**:真实 hidx 头部为定长 64 B,含 `header_len`(6..8)、头部 CRC(36..40)
> 与 `0..64` 的对齐 padding(`src/index/hidx.rs` 模块文档为逐字节权威)。
> `key_id`/`codec` 可选扩展区随加密/压缩(L11,设计 [04 §2.5](04-l2-persist.md))落地,
> 当前恒为 0("同一段三文件必须一致"的约束自 L11 生效);版本号与 vsec/msec 同代
> (`FORMAT_VERSION`),版本不一致一律拒读(I18)。

**目标形态(尚未兑现)**:mmap 惰性加载——打开段只读头部与 node_table,邻接 blob
由缺页按需载入,是"1M 条冷启动 < 1s"的主要支撑点([01 §1.1](01-overview.md))。

> **L3 现状**:`MmapSource`(feature `mmap`,默认开)已落地并统一用于段字节读取,
> 但当前仍**整段载入内存**后解码;真正"只读头部 + 邻接缺页惰性驻留"需让
> `ReaderView` 持有段句柄(`SegmentSource`),属后续收尾的段句柄重构(**尚未落地**,
> 见 [14 §4](14-testing.md))。故冷启动目标由后续收尾兑现,本层只提供 mmap 读路径优化。

## 11. 参数默认值

| 参数 | 默认 | 作用 | 上调的代价 |
|---|---|---|---|
| `M` | 16 | 上层度数 | 空间 ≈8M B/节点(=4·M0),构建时间线性涨 |
| `M0` | 2M=32 | 第 0 层度数(近邻密度) | 空间 ≈4·M0 B/节点,召回↑ |
| `ef_construction` | 200 | 构建探查宽度 | 构建时间线性涨,图质量↑ |
| `ef`(查询) | 64 | 查询探查宽度 | 延迟线性涨,召回↑ |
| $m_L$ | $1/\ln M$ | 层级骰子(由 `M` 派生,不在 `HnswParams` 中单独暴露) | 一般不动 |

> **默认值与召回门槛**:`ef=64` 是延迟优先的默认值;要达到
> [14 §4](14-testing.md) 的 Recall@10 ≥ 0.95 门槛,基准与验收显式使用 `ef=128`
> (文档算例与示例亦如此)。调用方按"召回/延迟"需求在 [64, 512] 区间自调。
> 段内行数不超过 `Tuning::brute_force_max_rows`(默认 2048)时查询恒走暴力扫描(严格大于才走图)
> ([16 §2](16-api-reference.md));**图可能仍随 flush 预建**(节省首次查询的构建停顿),
> 但查询路径不读它,`stats().segments[*].index_nodes` 因此可能非 0(设计 05 §11)。
>
> **建库校验**:`HnswParams` 在 `Builder::build` 入口强制 `m ≥ 2`、`m0 ≥ m`、
> `ef_construction ≥ 1`、`1 ≤ ef_search ≤ Limits.ef_max`、`m`/`m0 ≤ 4096`
> (`FC-INDEX-PRE-001`);越界返回 `Config`/`LimitExceeded`,绝不静默。

### 11.1 调参决策与常见误区

| 目标 | 先动哪个旋钮 | 说明 |
|---|---|---|
| 召回不够(Recall@10 < 0.95) | `ef` ↑(64 → 128 → 256) | 最直接;延迟近似线性涨 |
| 召回够但延迟高 | 开 i8 量化([08](08-l6-quant.md));再考虑 `ef` ↓ | 量化降带宽,不改精排分 |
| 构建太慢 | `ef_construction` ↓;并行度 ↑ | 会略降图质量,需重测召回 |
| 内存/磁盘吃紧 | `M`/`M0` ↓;设有限 `history_horizon` | 图变小但召回下降,历史不再永久 |
| 过滤后召回差 | 先看选择性 `s`,必要时走暴力档(§8) | 三档阈值可配,见 [16 §2](16-api-reference.md) |

**常见误区**:

1. 直接比较 `score` 数值而非走 `Metric::better`——欧氏是"越小越优",会排反;
2. 把 `ef` 当成"返回条数"——返回由 `top_k` 决定,`ef` 只控制探查宽度;
3. 期待 compaction 前后近似结果一致——图重建会改变邻接(§6.2 确定性边界);
4. 用默认 `history_horizon=None` 却频繁 `update`——历史节点会拖累当前搜索(§7);
5. 段行数不超过 `brute_force_max_rows` 时以为 HNSW 生效——实际恒走暴力扫描(§11)。

## 12. 层边界契约(L3 → 上层)

**向上提供**:

1. `HnswIndex::build(nodes, params, metric) -> Self`(构建;compaction 复用,见 `rebuild.rs`);
2. `VectorIndex::search(&IndexSearch) -> TopK<(RowId, SlotId)>`
   (`alive` / 过滤位图 / `ef` 由调用方传入,度量取自索引自身,三档策略内聚于 `filtered.rs`);
3. `serialize() -> Result<Vec<u8>>` / `load`(hidx 编解码,布局 §10;长度字段超限返回结构化
   错误而非截断;无增量 `insert`,compaction 整体重建);
4. 段内入口点与统计(节点数/层数)经 `stats()` 暴露(`SegmentStat.index_nodes/index_levels`)。

**依赖**:L0(`simd` 距离、`TopK`、`bitset`、标识类型)、L1 的索引抽象
`memory::index::{VectorIndex, IndexFactory}`(L1 只依赖 L0;L3 依赖 L1 不构成反向穿透),
以及 L2 `persist` 的帧编解码原语(`Cursor`/`crc32`/`FORMAT_VERSION`,hidx 布局与 vsec/msec
同代)与 `SegmentSource` 读入(方向仍 L3 → L2 → L1 → L0);`MmapSource`(feature `mmap`,
默认开)为读路径优化。
**不变量**:同一段内,搜索结果 ⊆ alive 位图 ∩ 过滤位图(alive 由可见性规则生成,含 `as_of`);
死节点与未被 alive 选中的历史版本只可穿越、不可入选;图与入口的结构约束
(每层度数 ≤ M0/M、入口 = 最高层、无自环)在构建与 hidx 载入两条路径恒成立(`FC-INDEX-INV-007`);
`ef → ∞` 时结果收敛于段内暴力扫描(见 [14 §3](14-testing.md))。

## 本章小结

- NSW = 小世界图 + 贪心路由;分层把"长程跳转"与"短程精修"分开。
- 层级分配是几何分布 $P(\ge l)=M^{-l}$,层高 $O(\log_M N)$。
- 构建/搜索/启发式选邻的完整算法;复杂度 $O(N \cdot d \cdot ef_c \cdot M_0)$ 构建、$O(d \cdot ef \cdot M_0)$ 查询。
- 墓碑删除:遍历可穿死节点、结果只收活节点;物理清理交给 compaction 整体重建。
- 过滤三档策略按选择性自适应;跨段归并;`ef → ∞` 收敛于暴力(§12)。
